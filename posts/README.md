# Posts Directory

This directory contains blog posts for the SVGViewer website. The posts are written in Markdown format with frontmatter metadata.

## File Structure

```
posts/
├── README.md                 # This file
├── index.json               # Auto-generated blog index (DO NOT EDIT MANUALLY)
├── welcome.md               # Individual blog posts
├── svg-to-png.md
└── ...other-posts.md
```

## Blog Post Format

Each blog post should be a Markdown file with frontmatter containing the following required fields:

```yaml
---
title: 'Your Blog Post Title'
date: '2024-03-03'
description: 'A brief description of your blog post content'
---

# Your Blog Content

Write your blog content here in Markdown format.
```

### Required Fields

- `title`: The title of the blog post
- `date`: Publication date in YYYY-MM-DD format
- `description`: A brief description for SEO and preview

## Managing the Blog Index

The `index.json` file contains metadata for all blog posts and is automatically generated. **Do not edit this file manually.**

### Generating the Index

To regenerate the blog index after adding, modifying, or deleting blog posts:

```bash
# Using npm/bun
bun run generate-posts-index

# Or directly
node scripts/generate-posts-index.js
```

### What the Script Does

1. Scans all `.md` files in the `posts` directory
2. Extracts frontmatter metadata (title, date, description)
3. Sorts posts by date (newest first)
4. Generates `index.json` with structured metadata
5. Provides validation warnings for missing required fields

### Index File Structure

The generated `index.json` has the following structure:

```json
{
  "generated": "2024-03-03T10:00:00.000Z",
  "count": 8,
  "posts": [
    {
      "slug": "post-filename",
      "title": "Blog Post Title", 
      "date": "2024-03-03",
      "description": "Blog post description"
    }
  ]
}
```

## Adding New Blog Posts

1. Create a new `.md` file in the `posts` directory
2. Add proper frontmatter with required fields
3. Write your content in Markdown
4. Run `bun run generate-posts-index` to update the index
5. The new post will automatically appear on the blog page

## Performance Benefits

This indexing system provides several advantages:

- **Static Import**: The `index.json` is imported at build time, eliminating runtime file system operations
- **Build-time Optimization**: Next.js can optimize the JSON data during the build process
- **No Runtime Parsing**: Post metadata is pre-processed and embedded in the bundle
- **Zero File System Calls**: No `fs.readFileSync()` or path operations at runtime
- **Better Tree Shaking**: Only the required data is included in the final bundle
- **Scalability**: Performance remains consistent as the number of blog posts grows

## Workflow Integration

Consider adding the index generation to your deployment pipeline:

```bash
# In your CI/CD pipeline
bun run generate-posts-index
bun run build
```

This ensures the index is always up-to-date in production.
